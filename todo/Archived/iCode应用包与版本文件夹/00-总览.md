# iCode 应用包与版本文件夹：总览

> 建立时间：2026-08-25
> 涉及项目：`instant-app`（iCode / 生成应用 / 应用包 / VFS）
> 状态：第一至六期已全部实施（2026-08-25；第六期调查判定可集成，走结束 A，Less 已上线）

目标：iCode 程序变成系统里的生成应用，源码按版本落在应用包文件夹里。桌面只跑当前最大正式版；iCode 只编草稿；发布把草稿升格成新的最大正式号。每个版本是一棵文件树：第一期当网站根；第四期起也可以是 TSX 工程（开发面按模块转译，发布写入单文件产物，桌面只跑该产物）。

动手顺序以本目录为准。与旧实现冲突时改实现，不另起一套平行身份长期并存。

## 分期

**第一期（`01-第一期.md`）** 就是已经讨论收口的那份计划：

- 砍掉 iCode 内部项目整包 JSON，迁到应用包 `Versions`（整数正式版 + `Draft`）。
- 运行只认最大正式号；iCode 只改草稿；发布升格并立刻再拷草稿。
- 每版本一份清单 JSON（名字、图标、颜色、能力等）；用户数据跨版本共用；聊天在版本树外。
- 版本文件夹当网站根，树内相对引用必须能解析。
- 多文件 = 能拆开的静态网站（主网页 + 脚本 / 样式 / 图片等邻居文件），不是完整工程。
- 微应用默认仍是 HTML/CSS/JS。第一期不用 Preact，不上构建链。
- 商店原应用只许复制、不许改；导入导出整包，冲突则副本。

**第二期（`02-第二期.md`）** 是单线上的版本治理，不上分支：

- 看见有哪些正式号、哪一档是当前最大号。
- 删除已经不是最大号的旧档（入口在 iCode，文件管理器仍不准删正式版）。
- 基于某一正式版拷出新的最大号；桌面改跑新号；更大的旧号若还在就留着直到用户去删。
- 不要命名分支、不要钉在非最大号运行。倒带靠「再接一档新的」，不靠删掉当前最大号。

**第三期（`03-第三期-AI编辑代理化.md`）** 是把 iCode 的编辑引擎整体换成系统 Agent 框架：

- 砍掉流式 SEARCH/REPLACE，iCode 聊天复用 vscode AI 那套 agent 循环 + 受控终端，按路径读写草稿树。
- 能力请求改为独立工具；写入硬限当前草稿，读取放开；AI 用量照常计入统计。
- 终端只是 iCode 开发面基础设施，生成应用本身仍不带终端。

**第四期（`04-第四期-JSX工程.md`）** 是工程化与发布收口，不是装包生态：

- 无安装清单；约定入口 `main.tsx`；标准模块引用；系统提供 Preact。
- 开发面：草稿按模块转译 TSX，保持多文件形态给预览（浏览器里跑 esbuild-wasm，不是本机打包器）。
- 发布面：升格后打成一份单文件写入该正式号的约定产物目录，与源码同夹共存；桌面只跑这份单文件。
- 新应用默认按 TSX 工程生成；旧纯网页不强制迁移。
- 不要第三方依赖、类型检查、Less；「不上终端」指生成应用运行时，与第三期的开发面终端不冲突。

**第五期（`05-第五期-类型检查.md`）** 是旁路类型检查：

- 浏览器里跑完整 TypeScript 检查器（宿主已有库或日后 TypeScript 7 的 WASM，同一位置替换）。
- 失败不挡预览转译、不挡发布打包、不挡桌面跑已有单文件。诊断给 iCode 和模型改源码用。

**第六期（`06-第六期-Less.md`）** 是 Less 的探索，产品落地不承诺：

- 先在本系统硬约束下做调查和最小试验（浏览器、无本机进程、版本文件夹、单文件发布）。
- 能集成再收成预览/发布能力；**证明确实没有可能，则只交报告、不上 Less**，第四期保持普通 CSS。
- 与第五期正交。

**以后再单独立项（不要塞进第一至六期）：**

- 运行指针（钉在非最大号）。
- 真正的分支（两条线、各自的尖）。
- 按版本归档聊天快照。
- 把应用商店更新也改成整数版本文件夹。
- 第三方依赖、包安装、完整打包配置。
- 把类型错误改成发布门禁。
- 其它 CSS 预处理器、CSS Modules。

## 阅读与动手

先读 `01-第一期.md` 再动手。第一期做完再做 `02`、`03`、`04`（二三与四各自正交；建议先 03 再 04）。第四期做完后，`05` 与 `06` 互不阻塞，可按产品优先级选一条先做。不要把治理面提前混进第一期的迁移；不要把第三期的 agent 引擎提前混进第一期的静态网站根；不要把第四期的工程与单文件产物提前混进静态树；不要把第五、六期提前混进第四期。
