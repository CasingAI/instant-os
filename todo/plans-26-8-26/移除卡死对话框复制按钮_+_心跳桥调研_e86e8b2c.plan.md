# 移除「复制最近诊断」按钮 + 心跳桥调研

## 一、回答：复制按钮是哪个 commit 加进来的？当时为什么？现在还需要吗？

- **加进来**：`2a6b7ee feat: 系统诊断日志、npm run/tsc 加固与 VFS 热路缓存`（2026-07-24）。当时是为了给「自举 `npm run build` 假死」提供跨标签可读的面包屑；按钮把最近 30 条诊断拷到剪贴板，便于粘到 issue 里。
- **已被取代**：`1976062 feat(os): 诊断日志升级为独立 Worker 黑匣子并全系统埋点`（2026-08-25）。主线程只负责 `postMessage`；独立 Worker 心跳判定主线程未响应并**写盘到独立 IndexedDB**。事件日志「系统」页重做后，残留自动出现在那里。**主线程冻死时复制按钮也点不动**，所以按钮的实用价值已经消失。
- **结论**：可以去掉。文案提示用户去「系统日志」查看即可。

## 三、卡死调查：心跳桥（postMessage）路径

### 3.1 现状回顾

- **iframe 端**（`src/apps/generated/inject-generated-app-heartbeat-bridge.ts:33-50`）：每 300ms 调 `parent.postMessage({ type, appId, windowId, timestamp, memory }, '*')`
- **宿主端**（`src/os/generated-app-heartbeat-context.tsx:185-220`）：监听 `window.message`，命中后清零 `consecutiveMisses`
- **死锁阈值**（`src/apps/generated/generated-app-heartbeat-types.ts:5-11`）：连续 33 × 300ms ≈ 10 秒无心跳 → 弹卡死对话框
- **隔离模式**（`src/apps/generated/use-generated-html-iframe.ts:141-151`）：sandbox 为 `allow-scripts allow-forms`（**无** `allow-same-origin`），改用 Blob URL 加载

### 3.2 假设与对应排查点

用户重点关心 **"宿主主线程被卡 → postMessage 队列堆积"**。我会在**执行阶段**按这个顺序排查（不写代码，先出报告）：

1. **`postMessage` 队列是否被饿死**
   - 阅读宿主 `useEffect` 中的 `addEventListener('message', onMessage)`（`generated-app-heartbeat-context.tsx:186-219`），看回调里有没有重同步操作
   - 同理检查 iCode 自己的 `onMessage`（`icode-app.tsx:837-886`）——里面会调 `setConsoleLogs` / `setDraftAppData` / `logRuntimeErrorToHostConsole`，大列表时是否做了长度截断
   - 看 `upsertGeneratedAppHeapReport`（被 `onMessage` 调）有没有同步 IndexedDB 写入

2. **跨进程消息是否会丢**
   - 隔离模式 iframe 跑在独立 renderer 进程。`parent.postMessage` 在 Chromium 里跨进程是 IPC；若主线程一直跑长任务（VFS / npm / VM），IPC 队列也可能堆积
   - 验证方法：隔离模式 vs 同源模式各跑一遍，看哪个更容易触发卡死弹窗

3. **iCode 预览内的子应用是否真的卡死**
   - `inject-generated-app-heartbeat-bridge.ts:50` 是 `setInterval`——**任何同步死循环都会让定时器停摆**。这正是设计本意。
   - 井字棋3D 的代码不在仓库里（运行时用户生成），但 `icode-app.tsx:758-778` 已有"预览应用未响应，可能是代码中存在死循环"的 console 警告——**这条警告和全局死锁弹窗是同一机制**，可对照时间戳确认到底是预览卡死还是宿主卡死
   - 关键判别：如果 `isWindowFrozen(previewHeartbeatWindowId)` **先**触发但**没**立即出现 10 秒弹窗 → 是宿主主线程被别的事拖住

4. **iCode 自身宿主代码的潜在重活**
   - `icode-app.tsx:888` 之后有"草稿树变更监听"——agent 写文件 → 重新构造 `preparedHtml` → 写回 iframe，链路长
   - 搜索同步 `await` / `while` / `for(;;)` 模式
