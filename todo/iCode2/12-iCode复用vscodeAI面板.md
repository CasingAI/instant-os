# 第十二期：iCode 复用 vscode AI 面板

> 建立时间：2026-08-26
> 期次：第十二期
> 涉及项目：`instant-app`（iCode / 生成应用 / 应用包 / VFS / vscode AI 框架）
> 状态：待实施（本期是开工依据）
> 前置：第一期、第三期（均已实施）
> 与第二 / 四 / 五 / 六期解耦；与第八至十一期正交，互不依赖
> 衔接稿：`07-衔接-对话面板.md`（拍板过程）。本文是唯一执行面。

目标：把 iCode「对话」tab 里的简化聊天外壳换成系统已有的 vscode AI 面板。引擎（agent 循环、受控终端、整轮回滚、草稿硬限）第三期已经接好，本期不动。删掉旧消息形态和简化渲染。聊天仍绑在应用上、不进版本树。

## 1. 为什么要有第十二期

第三期换的是引擎：模型已经在用 vscode 那套工具循环改草稿。外壳还是 iCode 自己的简化气泡、旧存取、旧能力确认对话框。面板上有的三档模式、附件、用量、面板内横幅，对话 tab 里都没有。

本期只换外壳，不重做引擎。

## 2. 已拍板规则

### 2.1 不再维护 iCode 自己的聊天形态

删掉只服务于旧对话 UI 的类型、气泡渲染、旧存取。旧聊天文件留在盘上当只读存档，UI 不再读、不迁移、不投影成新会话。第一次用新面板时从空对话起步。

### 2.2 挂载点

「对话」仍是调试面板里的一页。打开这一页就渲染 vscode 那块 AI 面板，喂 iCode 自己的 host。源码 / 配置 / 版本 / 数据 / 日志不动。整体布局不改成「侧栏 AI + 右侧源码」。旧的「清空对话」从工具栏拿掉。

### 2.3 host：iCode 自己一套，不读 vscode 偏好

- 模型：用同一套可选模型列表，偏好写在包的 Developer 里，不读 vscode 偏好。
- 模式：agent / plan / ask 三档都开，默认 agent。plan 下模型不改草稿，产物写在草稿树的计划子目录；host 不打开计划文件。点「实施」切回 agent，把计划路径喂给**当前**会话下一轮，不新开会话。ask 下只回答、不改文件。
- 子代理：不启用。
- 附件：开。粘贴 / 拖入走面板自带流程，图传到当前模型服务，上下文里是远端地址或内嵌数据，不落到 VFS。需要时给本机选图入口。不造「本地文件路径」附件工具。
- 上下文用量：从草稿树和类型检查问题构造。
- 终端：沿用第三期已经接好的受控终端宿主。
- 会话：每个应用一个会话，界面不暴露「新建会话」。落盘到包 Developer，导出整包时带上；写入做短延迟合并，避免每条消息都打盘。

### 2.4 写硬限与读取放开

沿用第三期：只能写草稿树；读其它路径放开；用量统计已接线，本期不重接。

### 2.5 能力请求

能力标签（三维 / AI / 文件 / 终端）和写入清单这一条保留。确认不再用 iCode 自己的对话框，改走面板内嵌横幅：同意 / 拒绝 / 三十秒超时默认拒绝。vscode 侧把「请求切模式」收成通用的「请求用户拍板」，模式切换是其中一个用法；iCode 的能力请求走同一个入口。同意后写清单标签。vscode 主区切模式的观感不能被改坏。

### 2.6 预览刷新

草稿树变更监听保留，写完一轮自动刷预览。面板自带的「未确认变更」在 iCode 里关掉：agent 写完即落草稿。要不要做变更确认，以后单独立项。

### 2.7 补强（动手时按这里，不要再问）

- 源码上的「运行」保留，保存和运行分开。
- 「编辑上一条重发」要做；重发前按 vscode 那套把上一轮终端变更撤掉。
- 「停止」保留已落盘，不自动整轮回滚。
- 二进制资源在给模型的清单里只写路径，不塞内容。
- 运行时数据目录模型能读。
- 不把编辑器光标 / 选区注入给模型。

## 3. 明确不做的事

- 不把 AI 面板复制进 iCode 目录，复用 vscode 那份。
- 不读 vscode 偏好。
- 不留旧气泡当回退。
- 不重画整体布局。
- 不启用子代理，不在 iCode 里打开计划文件当编辑器。
- 不做变更确认流程。
- 不做按版本归档聊天。
- 不把附件图落到 VFS。
- 除「请求用户拍板」这一处外，不改 vscode / Produde / 帮助对该面板的用法。
- 不在本期做写时并发检查（那是第八 / 九 / 十一期）。

## 4. 建议实施顺序

1. vscode 侧：把「请求切模式」收成通用「请求用户拍板」；横幅共用。确认 vscode 主区切模式仍对。
2. 对话 tab 挂上面板骨架（三档模式和附件看得见）。
3. 会话落盘与恢复（每应用一个会话）。
4. host 接模型偏好、三档模式、上下文、类型检查问题、终端、落盘。
5. 附件接入（不落 VFS）。
6. 能力请求改走横幅；删旧对话框。
7. 删旧气泡、旧消息类型、旧存取。
8. 导出带上新会话文件；回归：写草稿、跨文件读、能力请求、用量、附件、治理面、预览刷新、vscode 主区切模式。

## 5. 验收清单

- 对话 tab 看到的是 vscode 那块 AI 面板；三档可切；附件按钮在。
- 提修改需求后模型改草稿，预览跟上；看不见旧气泡和补丁块。
- 换应用再换回来，聊天还在（按应用落在 Developer）。
- 草稿变更后预览自动刷新。
- 写到草稿树外被拒；正式版不可写；读其它路径不被拦。
- plan 不改草稿；ask 只回答。
- 未授予能力时面板内横幅，三十秒默认拒绝；同意后写清单。
- 无子代理面板；计划文件不在 iCode 里打开；无变更确认拦截。
- 附件不落 VFS；未配视觉模型时附件不可用并说明原因。
- 用量统计仍能看到。
- 旧聊天文件留着但不被 UI 读。
- 治理面（看 / 删旧档 / 基于旧档新建、发布、商店复制、导入导出）与改前一致。
- vscode 主区切模式、计划横幅与改前一致。
- 布局仍是左预览 / 右调试面板（对话、源码、配置、版本、数据、日志）。
