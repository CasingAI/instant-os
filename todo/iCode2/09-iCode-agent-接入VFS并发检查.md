# 第九期：iCode agent 接入写时并发检查

> 建立时间：2026-08-26
> 期次：第九期（iCode agent = 第八期原语 + 第十一期通道上的第一个拦截器）
> 涉及项目：`instant-app`（iCode / quickjs 实例 / vscode AI 终端会话）
> 状态：未实施
> 前置：`08-VFS-写时并发检查.md` + `11-运行时宿主syscall-hook.md`
> 与第十二期解耦；与第十期正交

目标：iCode agent 经受控终端写草稿时，不再盲写。运行时记住这个实例「上次读到该文件时的版本」，写入时把期望版本交给第八期的 VFS 原语。对不上就拒绝；沙箱里看到权限类错误；agent 按主流 AI IDE 的方式先重读再写。

**和旧方案的本质区别**：不是改文件桥里四处写入，也不是在文件系统公开入口上挂全局钩子。而是在 **iCode 创建 agent 用的 Instant Node 实例那一处**，挂上一条「记读、写时带期望版本」的拦截器。

## 1. 为什么要有第九期

### 1.1 现状

- iCode agent 写草稿：终端里跑脚本 → 沙箱里的写文件。写根硬限（只能写草稿树）第三期已经有，越界即拒。
- 写时并发没做。文件桥写前会看一次状态，但只用它判断「是不是目录」，没有把「我上次读到的版本」交给存储层。
- 第十二期把「用户改的代码可能被 AI 覆盖」当成已知取舍。本期关掉这条取舍。

### 1.2 为什么不能「写前现看版本、再当作期望」

若在写入当下现看一次版本、把看到的值填成期望值：存储层比对的是「刚才」和「此刻」，几乎永远相等。agent 思考那几十秒里用户改的文件，照样被覆盖。那不是并发检查，是空转。

主流 AI IDE 做的是：**读的时候记住版本，写的时候核对该次读**。沙箱本身没有跨调用的记忆，记忆必须放在**这个实例的宿主侧**。这正是第十一期通道存在的理由。

### 1.3 为什么挂在实例上而不是文件系统公开入口

- 只有 agent 用的实例需要这套策略。用户自己在终端里写文件，应该就是写下去。
- 文件管理器保存、商店同步、github-desktop 不走这条实例，也不该被同一条全局策略误伤。
- github-desktop 要的并发语义不同，走第八期原语自己传期望版本（第十期），不走本期拦截器。

## 2. 已拍板规则

### 2.1 拦截器：按路径记住上次成功读到的版本

每个挂了本拦截器的实例，宿主侧有一张「路径 → 版本」表，只活在这个实例上。

- 读文件 / 看状态 **成功且目标是文件**：记下该路径当前版本
- 写文件 / 追加 / 流式写：**若表里有这个路径**，把记下的版本填进第八期的「期望版本」再交给真正写入；**若表里没有**（新建，或从未读过就写）→ 不填，行为与现在盲写一致
- 写入 **成功**：清掉旧记录或改成新版本（写成功后再看一次状态，或若写接口将来返回新版本就用返回值）。避免连续两次写用同一个过期期望
- 写入因「版本不对」失败：表仍保留旧期望，直到一次成功的重读把它刷新——这样 agent 重读之前不会用过期期望把错误写穿
- 删文件成功：从表里拿掉

新建文件：看状态得到「没有这个节点」→ 不填期望版本 → 走创建。创建与「覆盖已有文件」的分界仍由文件桥现有逻辑负责，本期不重写。

### 2.2 只挂在 agent 用的实例上

挂载点：iCode（以及同一套受控终端宿主）**为 agent 会话创建 Instant Node 实例**的地方。用户点开的普通终端、Virtual JS、包安装脚本：**不挂**。

若 vscode 侧 agent 终端和 iCode 共用同一套「创建实例」路径，只要那条路径是 agent 会话，就一起受益；若分叉了，只改 iCode 这条，不顺手改用户 REPL。

### 2.3 错误怎么回到 agent

第八期抛「版本不匹配」。文件桥把它收成沙箱能看懂的权限类错误，文本里带路径、期望版本、当前版本，并写明请重读后再试。agent 提示词**不**解释背后机制；错误文本足够模型走「先读再写」。

### 2.4 读路径对沙箱保持原样

沙箱里读文件的返回值仍然只是内容，不带版本号。版本只活在宿主侧那张表里。不把版本泄漏进脚本，免得脚本自己搞一套对账。

### 2.5 和写根硬限正交

写到草稿树外：仍是「根未授权」。写在树内但版本不对：仍是权限类错误，文本区分原因。agent 看到同一类错误码，靠文本区分。

## 3. 验收清单

- agent 先读后写同一份草稿，中途无人改：写入成功。
- agent 读过之后、写下之前，用户在源码侧改了同一文件：写入被拒；agent 重读后再写成功。
- agent 从未读过就写（新建）：不填期望版本，与现在一致。
- 用户自己的终端里写文件：不挂本拦截器，不被拒。
- 沙箱读文件的返回值不变。
- 写根硬限不变。
- 两个 agent 实例各有各的表，互不串。

## 4. 明确不做的事

- 不改 iCode agent 的提示词，不向模型解释版本机制。
- 不改沙箱里读文件的返回值。
- 不在文件系统公开入口上注册全局钩子。
- 不把本拦截器默认挂到所有 Instant Node 实例。
- 不做自动合并 / 三方合并。
- 不在本期清理任何「对话面板」侧的内存版本表（第十二期不会建这个表）。

## 5. 建议实施顺序

1. 确认文件桥把第八期的「版本不匹配」收成带路径 / 期望 / 当前的权限类错误。
2. 实现本拦截器（记读、写时填期望、写成功后刷新、删后剔除）。
3. 在 iCode agent 创建实例处挂上它。
4. 测：先读后写；读后被外部改；从未读就写；用户终端不受影响；两实例隔离。
5. 回归：草稿硬限、预览刷新、受控模式日记。
