### 3.3 host：iCode 端新写

按"iCode 自己一套"实施，不读 vscode 偏好（`src/apps/vscode/vscode-prefs.ts`）：

- 模型选择：iCode 用 `useVscodeAiTextModels` 拿可选模型，写一份 iCode 自己的模型偏好存储（路径同样放包 Developer，例如 `Developer/ai-prefs.json`），形态可对齐 `VscodeAiModelOptionPrefs`。
- 模式：**三档全开**——`agent` / `plan` / `ask` 都可切换，对应面板内嵌的 `ModeSwitchBar`（保留 vscode 的"AI 想从 X 切到 Y，请用户同意"行为）。默认 `agent`（与第三期"AI 改草稿"行为一致）；切到 `plan` 后允许 model 写 `*.plan.md`、iCode host 端用 `openPlanFile` noop（`plan` 模式下不允许 agent 改草稿）；切到 `ask` 后 model 不改任何文件，只回答。
- 子代理：iCode 端不启用（不传 `subAgentsEnabled`，与子代理面板相关 props 不传）。
- 计划文件：`plan` 模式产出的 `*.plan.md` 不在 iCode 中"查看/实施"——iCode host 提供 noop 的 `openPlanFile`。`plan` 模式仍允许被切到并生效（plan-ready banner 可展示在面板里），点击"实施"在 iCode 端表现为切回 `agent` 并把 plan 文件路径作为提示词喂给**当前** chat session 的下一轮 agent（**沿用当前会话，不新开**，与第三期 chat 流程一致）。
- 附件：iCode 端**开**。图片粘贴/拖拽走 vscode AI 面板自带流程（`vscode-ai-attachments.ts`），**协议上**与 vscode 一致：图片上传到当前 AI provider（OpenAI vision 那一套），模型上下文里看到的是 provider URL/base64，iCode 端不存到 VFS。iCode 端仅在需要时给 `SystemOpenDialog` 一个本机图片选择入口；iCode 自己的 `ai-prefs.json` 里仍可保存 vision 模型偏好（与 vscode 同样的 `useVscodeAiCapabilityTags` 检测），但**不**保存附件图片到 VFS。**本期的附件实现就停在 vscode 那一套的 iCode 接入层**，不造"本地文件路径"附件工具。

### 3.5 能力请求：复用 vscode 模式切换的"面板内嵌横幅"形态

`IcodeCapabilityTag` 概念保留（3D / AI / Files / Terminal；写进 `manifest.tags` 这条不破），但**确认 UI 不再是 iCode 自己的 `WindowModal`**，而是用 vscode AI 面板里 `ModeSwitchBar`（`src/apps/vscode/vscode-ai-panel.tsx:925-993`）那一套"面板内嵌横幅 + 同意/拒绝按钮 + 30s 超时自动拒绝"的形态。

实施要点：

- **vscode 端改一次**：把 `requestModeSwitch` 提为通用 `requestChange`（或同义名）。形态上把 `target: VscodeAiMode` 换成更通用的"想做什么 + 描述 + 两个动作标签 + resolve(decision)"，模式切换是该通用 API 的一个内置 case（这样 vscode 自己走原路，iCode 接更广义）。ModeSwitchBar/PlanReadyBar 复用同一个内嵌渲染。
- **iCode 端调用**：在 `createIcodeAiTools` 的 `request_capability` 工具（`src/apps/icode/icode-agent.ts:122-159`）里把 `input.requestCapability(tag, reason)` 改成调用 host 注入的 `requestChange`，把 `tag` 映射成"授予 X 能力"的动作标签，`reason` 作为描述。`requestChange` resolve `'approved'` 时写 `manifest.tags` 并把已授予结果回给工具（行为与第三期验收项一致）。
- 删除 iCode 端 `IcodeCapabilityTag` / `capabilityPrompt` / `WindowModal` 能力确认对话框（`src/apps/icode/icode-app.tsx:2741-2775`）以及 `capabilityPrompt` / `grantCapabilityPrompt` 状态。

## 6. 验收清单

- iCode「对话」tab 渲染的是 `<VscodeAiPanel />`，与 vscode 应用的 AI 面板视觉与交互一致；模式三档（agent / plan / ask）可在面板内切换；附件按钮可见。
- 用户在 iCode 里提修改需求，模型经工具循环直接改草稿树内文件；预览反映新内容；对话区看不到旧气泡、自定义折叠面板、SEARCH/REPLACE 块。
- 切到下一个 iCode 应用、再切回来，聊天历史仍在（按 appId 落 `Developer/ai-sessions.json`）。
- 草稿根文件变更后预览自动刷新（沿用第三期 `subscribeFilesWatch` 链路）。
- 写入草稿树之外路径被拒；正式版文件夹任何情况下不可写。
