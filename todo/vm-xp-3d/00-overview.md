# XP 内跑 3D 游戏：总览

> 建立时间：2026-08-23  
> 涉及项目：`instant-app` / `Instant-virtual-machine`  
> 外部参照：v86gl（改过的 v86 + 客机代理 + 宿主执行器），不是把游戏重编译成网页。

目标：用户在 Instant OS 的虚拟机里启动 Windows XP，打开一份现成的 Direct3D 9 游戏，三维画面由浏览器 GPU 画出来，而不是走模拟器那条慢的桌面显存。

---

## 1. 现在缺什么

`Instant-virtual-machine` 用的是原版 v86。外面那张屏只贴客机桌面像素。XP 里的 Direct3D 如果真的在画，也打在模拟器的假显卡上，最后变成 2D 帧。浏览器从来没有收到「这是一次三维绘制」这种信息。

因此不能指望「外面是 WebGL、里面是 Direct3D」自动接上。必须自己造一条过墙通道。

---

## 2. 整条通路（四段）

1. **客机拦截**  
   XP 里放一份假的 Direct3D 9 库，游戏以为自己在打真卡。调用被记下，不在客机里真正光栅化三维。

2. **过墙**  
   自定义图形设备把这批命令从客机内存送到网页。这不是原版 v86 就有的能力，要改模拟器。

3. **宿主执行**  
   网页解开命令，按 Direct3D 9 的语义在浏览器 GPU 上画。画面落在叠加层上，盖住（或完全取代）桌面那张屏。

4. **让游戏能跑起来**  
   把客户端和假库送进 XP；尽量藏掉桌面；键鼠仍要打进那扇游戏窗；用快照避免用户看见开机。

这四段缺任何一段，三维都出不来。翻译「Direct3D → WebGL」只是第 3 段里的一部分。

## 4. 明确不做的事

- 不要把 `d3d9-webgl` 整包推进运行时当插件。游戏是 XP 里的现成程序，不会去调它。它的固定管线画法可以当第 3 段的参考，见 `03-host-executor.md`。
- 不要把游戏源码重编译成网页。那是另一条产品，和「虚拟机里跑 exe」无关。
- 不要在 `instant-app` 里做 GPU 执行。模拟器和画布都在 `Instant-virtual-machine` 的 iframe 里；桌面这边只传开机参数、镜像和输入。

---

## 5. 成功长什么样

最低成功：XP 里一个极简 Direct3D 9 程序（清屏 + 一个带纹理的三角形），叠加层上能看见，拖窗口时盖板跟着走。

产品成功：用户几乎只看见游戏画面；XP 在幕后用快照恢复；完整客户端能进三维场景。桌面、崩溃框、非三维控件可以后置。

---

## 6. 建议的仓库分工

- `Instant-virtual-machine`：改过的模拟器产物、宿主桥、叠加画布、开机时打开图形设备。这部分在 Mac 上用现有网页工具链即可，不编 Windows 库。
- 客机资产（假 Direct3D 库、送文件代理、精简 XP 快照）：单独管理，不要塞进 git 大镜像。假库在 Mac 上交叉编译，方案见 `02-guest-d3d-proxy.md` 第 3 节（首选 llvm-mingw 32 位旧运行库）。
- `instant-app`：设置项（是否启用三维加速、是否隐藏桌面）、协议里多几个开关，必要时把游戏目录交给已有的文件共享通道。
