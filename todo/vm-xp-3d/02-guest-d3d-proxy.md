# 计划 2：客机 Direct3D 拦截

> 依赖：计划 1 的设备至少能写进一批数据  
> 产物：XP 里的假 Direct3D 9 库（以及如有需要的假 OpenGL 库，后置）

游戏只会加载系统或自己目录里的 Direct3D。要把调用送出 XP，必须在这里拦。

---

## 1. 角色

假库对外看起来像真的 Direct3D 9：创建设备、设状态、画、提交画面。对内不做真正的三维光栅化，只做三件事：

- 维持游戏需要的对象和句柄（纹理、顶点缓冲、设备），让游戏以为成功了。
- 把绘制与资源上传打成批次，写进计划 1 的设备。
- 每次提交画面时带上窗口客户区在桌面上的位置和大小，供外面盖板对齐。

像素读回（把外面画好的帧再拷进 XP）这一阶段明确不做。游戏若坚持读前缓冲，返回「不支持」即可。

---

## 2. 能力要分阶段暴露

不要一上来宣称自己是完整的 2009 年显卡。

**阶段 A（通路）**  
清屏、创建纹理、画一次带纹理的三角形、提交画面、报窗口矩形。能力查询只承认这些。

**阶段 B（固定管线）**  
变换、材质、少量灯、常用混合与深度、常见纹理格式。用来跑极老的三维 Demo。

**阶段 C（着色器）**  
顶点/像素着色器字节码原样送出，由计划 3 翻译。这是跑跑一类客户端的门槛。

游戏问「你有没有某能力」时，没有的就说没有，让它走退路或放弃，好过假装有再画错。

---

## 3. 在 Mac 上怎么编出 XP 能加载的库

计划一不走这条工具链。这里只编 **32 位用户态**假库和配套 Demo。内核驱动不在本阶段，也不用这套编译器。

目标格式必须和跑跑那份代理一样：32 位 Windows 可执行文件、子系统 XP、链接到旧的 C 运行库。64 位库、面向新系统的运行库，XP 都会直接拒绝加载。

**首选：llvm-mingw，目标选 32 位，运行库选旧的那套（不要新系统那套）。**  
一套编译器就能在 Intel / Apple Silicon 的 Mac 上交叉编出 XP 用的库，和 v86gl 那份用 MinGW 编出来的形态接近。编完用文件类型确认是 32 位，再确认导入的系统库都是 XP 里有的。

**备选：Zig 当交叉编译器。**  
安装更轻，一条命令指定「32 位 Windows」。仍要把子系统钉在 XP，不要用工具链的默认最低系统版本。适合先编通 Demo，正式假库也可以继续用。

**兜底：容器里的 32 位 MinGW。**  
本机工具链闹别扭时，用 Linux 容器里的 32 位 Windows 交叉编译器，产物拷出来照样进 XP。不依赖本机 Homebrew 有没有 32 位目标。

不要用的：

- Visual Studio / 驱动工具包（Mac 上没有，内核驱动才需要，本阶段不做）
- 64 位 MinGW（客机是 32 位 XP）
- 面向 Vista 及以后的 C 运行库

验收编译器本身（还没测绘制）：

- [ ] 本机固定一种首选工具链，写进仓库脚本，避免每人编出来的库不一样。
- [ ] 产出确认为 32 位、子系统为 XP。
- [ ] 同一工具链编一个「什么图形都不做、只弹一句启动成功」的 Demo，丢进 XP 能跑起来。这一步只证明加载和 Win32 入口，不证明三维通路。

源码在 Mac 上写；**行为只能在 XP 客机里验。** 编过了不等于画对了。

其它约束不变：先用自己写的极简 Demo，不要用完整游戏当第一支探针；假库放在 exe 旁边，避免改系统盘；失败写客机日志，桌面藏起来之后这是唯一的客机侧线索。

---

## 4. 任务

- [ ] 定协议：批次头、句柄怎么编号、资源上传怎么跟绘制命令排在一起。与计划 3 共用一份说明，两边不要各写各的。
- [ ] 选定并固化 Mac 交叉编译工具链（见第 3 节），先让空 Demo 在 XP 里能启动。
- [ ] 实现阶段 A，能在 XP 里被 Demo 加载。
- [ ] 打开计划 1 的设备失败时，行为要明确：要么拒绝创建设备（Demo 立刻失败），要么暂时不要静默掉进软件光栅。
- [ ] 提交画面时采集客户区矩形；全屏时客户区可能是空的，沿用上一次有效尺寸。
- [ ] 阶段 B / C 按里程碑再开，见计划 5。

---

## 5. 验收（阶段 A）

- [ ] Demo 能创建设备、清成固定颜色、提交后宿主收到对应批次。
- [ ] 移动 Demo 窗口，后续批次里的矩形会变。
- [ ] 未实现的读回接口返回失败，不卡死。

---

## 6. 和 OpenGL 的关系

若以后有 OpenGL 游戏，拦截方式同类，但协议不同。v86gl 把 OpenGL 交给另一套翻译。本计划只锁定 Direct3D 9。不要在假库里同时混两套 API。
