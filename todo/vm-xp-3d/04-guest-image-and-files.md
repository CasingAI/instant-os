# 计划 4：客机镜像、送文件、藏桌面

> 依赖：计划 1–3 的通路在 Demo 上已经出画  
> 相关：`todo/vm-host-filesystem-sharing.md`（Windows 不能走 9P）

这一段解决「游戏和假库怎么进 XP」以及「用户要不要看见整台 XP」。

---

## 1. 镜像策略

要跑 Direct3D 9 游戏，客机需要能加载 Win32 程序的 XP（或同等环境）。现在的预制是 Android 和 ReactOS，不能当这条通路的测试床。

- [ ] 准备一份专用 XP 磁盘：自动登录、尽量少的启动项、不要资源管理器也可以（后置）。
- [ ] 用快照冻结在「已经开机、假库已就位、可以立刻跑 Demo」的时刻。用户打开虚拟机时从快照恢复，不要看完整开机。
- [ ] 快照内存大小必须与开机配置一致（见 `todo/vm-snapshot-memory-mismatch.md`）。三维设备打开后先规定：快照不含未完成的 GPU 批次，恢复后游戏重新创建设备。
- [ ] 大镜像不进 git。用现有的本地盘 / 网络盘 / 流式读取即可。

系统盘建议只读或很少写；游戏、假库、Demo 放第二块盘或固定目录，方便换测试件而不重做系统快照。

---

## 2. 把文件送进 XP

三维通路不负责通用文件共享。这里只要能稳定把这些东西放进客机：

- 假 Direct3D 库
- 测试 Demo 或游戏客户端
- 可选：送文件代理的配置

可选做法（与共享方案对齐，选一条做通即可）：

1. **第二块磁盘 / 光驱**  
   开机前在桌面侧把目录打成镜像再挂上。最稳，适合假库和 Demo 这种不常改的东西。
2. **客机送文件代理**  
   v86gl 用模拟串口 + 客机小进程，按配置表把宿主文件写到指定盘。适合反复替换测试件。Windows 没有 9P，这条比硬做 SMB 现实。
3. **不要用**网页里的 `d3d9-webgl` 来送文件，它不管这个。

任务：

- [ ] 选定 1 或 2 作为开发期主路径。
- [ ] 约定游戏盘上的目录布局（例如 Demo 与假库同目录）。
- [ ] 若做串口代理：模拟器要开串口，运行时把宿主文件桥过去；配置表里系统盘只读、游戏盘可写。
- [ ] `instant-app` 只提供「把哪个宿主目录当作游戏盘」的设置，真正搬运在 iframe 或开机打包里完成。

---

## 3. 藏桌面（产品形态，后于出画）

通路验证阶段必须能看见 XP，否则无法判断是游戏没起来还是盖板错位。

出画稳定之后：

- [ ] 设置项：对外只显示三维画布（桌面屏不贴出来，或藏掉）。
- [ ] 游戏尽量全屏设备，盖板可以铺满，少跟窗口矩形。
- [ ] 客机仍要跑 XP 和 Win32，只是用户看不见外壳。不是把系统收成「只有游戏的固件」。
- [ ] 崩溃框、未走三维的控件会从视野里消失。必须保留客机日志和宿主统计，否则会「黑屏但不知道为什么」。

不要在第一阶段就关桌面。

---

## 4. 验收

- [ ] 从快照开机后，不手动装系统，就能在约定目录看到假库和 Demo。
- [ ] 替换 Demo 不必重做系统快照。
- [ ] 仍显示桌面时，能同时看到窗口边框和客户区里的三维（证明盖板在干活）。
- [ ] 藏桌面作为独立开关，关掉能立刻回到对照视图。
