# 计划 5：输入与验收阶梯

> 依赖：计划 1–4 在「仍显示桌面」模式下已经出画

画面对了不等于能玩。这一段把输入接上，并规定不要跳级。

---

## 1. 输入

### 1.1 对照期（桌面可见）

三维盖板不抢指针。点击打在桌面屏上，v86 原有键鼠照旧。游戏窗口必须在客机里保持前台，否则会出现「画面还在、点到了别的窗」。

- [ ] 假库或小助手在全屏时反复把游戏窗拉回前台（v86gl 已经遇到过前台丢失）。
- [ ] 验证：点客户区、拖标题栏、键盘进入 Demo，行为与不用三维加速时一致。

### 1.2 只显示三维时

盖板铺满之后，指针事件要改挂到三维画布（或容器），再注入模拟器的键鼠通道。

- [ ] 相对鼠标（第一人称、全屏）走指针锁定；窗口模式可用绝对坐标，按盖板矩形换算到客机屏幕。
- [ ] 键盘焦点必须留在 iframe。桌面侧已有向客机灌键盘的消息，藏桌面后仍要能用。
- [ ] 浏览器自己的快捷键不要误当成游戏输入；也不要让游戏抢走刷新、关闭标签。

声音继续走 v86 现有扬声器开关，与三维无关，但藏桌面时不要把扬声器默认关掉。

---

## 2. 验收阶梯（必须按序）

每一级过了再开下一级。完整游戏不当第一支探针。

### 第 0 级：设备空跑

计划 1。宿主能收到一笔测试批次。

### 第 1 级：清屏

计划 2–3 阶段 A。客机 Demo 清成纯色，盖板出现这块颜色。

### 第 2 级：一个三角形

带一张纹理、基本变换。拖窗口，盖板跟随。这是「通路打通」的定义。

### 第 3 级：固定管线小 Demo

灯、混合、再多一点状态。可用自写 Demo 或极老的固定管线样例。此时才值得翻 `d3d9-webgl` 里的固定管线画法当对照。

### 第 4 级：着色器小 Demo

自写、带一份简单顶点/像素着色器的程序。过了这一级，才具备跑 2004 年后多数商业三维客户端的前提。

### 第 5 级：低规格单机三维游戏

选 Direct3D 8/9、单机、配置很老、尽量少依赖读回像素的游戏。不要用反作弊、必须联网的客户端当第一款。

跑跑卡丁车可以当「同代参照」，但依赖本机假服务器和道具表，不是第 5 级的第一候选。要测它，先有自己的启动器/假协议，那是游戏侧的事，不是图形通路的事。

### 第 6 级：藏桌面的产品形态

只给用户看三维 + 声音。开机用快照。输入走 1.2。失败时桌面侧能看到宿主统计，而不是一块无说明黑屏。

## 5. 和现有虚拟机功能的关系

三维加速是附加能力。关掉时，虚拟机应用应与现在完全一样（Android / ReactOS / 普通 XP 桌面）。不要让图形 fork 破坏现有开机、流式磁盘、统计和键鼠。
