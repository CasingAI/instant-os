# 内部卷：按块写时复制（接近 APFS clone）

> 建立时间：2026-08-24；**2026-08-25 重写并归档**
> 涉及项目：`instant-app`（VFS / IndexedDB + OPFS 内部卷）
> 状态：方案存档，**暂缓实施**。仅 §6.0 无争议、可与本方案解耦先行；§6.1 起须先过 §10 的两道前置验证。

目标不变：复制大文件时内容只占一份空间；之后只改其中几段时，只为**被改到的段**再占空间，而不是整份再记一份。产品语义对齐 APFS clone，实现完全在 Instant 内部账本里，不调用本机 `clonefile`。

> **为什么重写**：旧版建立当天起，存储层连续合入大改——大文件正文改存 OPFS（`028ec95`）、偏移写原地落盘（`cdd2e07`）、内部卷稀疏分块（`15d740f`）、VM 实时写入走安静写入通道直写 OPFS（`fbd6ab7`/`7a8c901`）。旧版「大文件按 4MB 一块落在 IndexedDB 块表」的前提已不成立，且暴露出一个正确性缺口（见 §3.3）。目标与边界不动，模型与步骤全部重排。

---

## 1. 现在有什么（重写后的现状）

**共享与引用**：`/user`、`/dev`、`/tmp` 复制文件走 `cloneFileNodeWithSharedBlob`——两条目录项指向同一份内容记录，`refCount` 加一，配额只加节点元数据。任一侧整份重写、或范围写遇到共享内容时按**整份内容**分叉。终端改前副本（私有仓）也走这条路径。

**双后端**：

| 后端 | 适用 | 形态 |
|---|---|---|
| IndexedDB | 小文件、有洞文件、旧数据 | 整份 `bytes`，或块表 `[blobId, chunkIndex]`（流式写约 4MB 等长槽 + 尾块合并） |
| OPFS | 新建的大文件（超过约 25MB 溢出） | **单个整文件**，IndexedDB 只留索引记录（`backend:'opfs'` + 大小 + 引用），没有块表 |

**稀疏语义**（`createSparseFile`，VM 磁盘镜像用）：逻辑大小与实占 `storedByteSize` 分开记账；缺席槽读为全零；写零打洞移除槽。等长分槽文件的缺席槽不物化。

**范围写**：IDB 分槽文件按槽补丁（全零槽不落库）；OPFS 内容原地 `writeOpfsBlobRange`；独占（refCount=1）不拷贝，共享则换新 blobId。

**挂载卷（`/mount/...`）** 仍是浏览器目录授权、整份搬运，本方案继续不管。

## 2. 与真 APFS 差在哪

| | 现在 | APFS | 本方案 |
|---|---|---|---|
| 复制瞬间 | 共享整份内容记录 | 共享盘上的块 | 保持共享 |
| 第一次改几个字节 | **整份再占一份**（IDB 全槽重写；OPFS `copyOpfsBlob` 物理整拷） | 只新占被改到的 extent | **只新占被改到的段** |
| 空间账本 | Instant 配额 | 内核可见 | 仍是 Instant 配额 |

段粒度沿用现有槽大小（默认 4MB），不是盘上的 4KB。改 1 字节最多新占一段。「这是网页账本、接不上内核 clone」的差距不在本期。

---

## 3. 卡点（三条，比旧版多一条）

### 3.1 段没有独立身份（继承自旧版）

IDB 块表主键挂在「属于哪份内容 + 第几块」上，IndexedDB 按值存储，同一串字节写两个键就是两份。分叉时所有槽在新 blobId 下重存一遍。必须让**段自己成为可被多份内容引用的对象**。

### 3.2 OPFS 正文根本没有段结构（新增）

最大的受益者——GB 级磁盘镜像——正文是单个 OPFS 文件，块级 COW 若只做 IDB 块表恰好绕开它。共享的 OPFS 内容一旦有人范围写，`copyOpfsBlob` 把整个文件物理复制一遍：GB 级镜像改几 MB 触发整份拷贝，比旧版描述的问题更痛。

OPFS 没有硬链接，「每 blob 一个目录、目录内各存各的段文件」无法表达跨内容的共享。段必须升级为**全局命名对象**，内容记录退化为有序的段引用列表。

### 3.3 安静写入通道绕过 COW 判定（新增，正确性缺口）

VM 镜像挂载经 `openQuietBlobWriter` 直接持有 OPFS 文件句柄写入，全程不查 `refCount`。若这份内容正被克隆共享（先复制再挂载是正常操作），写入会**静默污染另一个副本**。这与块化无关，须最先修。

另有一个账目缺口：共享 OPFS 内容分叉时物理上整份复制，配额却只加本次写入字节数（`commitOpfsRangeWrite` 的 `capacityDelta`），账面与实占脱节。

## 4. 目标模型

- **段（segment）是一等公民**：稳定全局 id、自带引用计数、字节落在某个后端（IDB 段表或 OPFS 段文件）。
- **内容记录 = 有序段引用列表**（第几段、逻辑偏移），外加逻辑大小与实占大小。
- 缺席段 = 逻辑全零，不物化（保持稀疏语义）。写零打洞 = 移除该段引用并减计数。
- **复制**：维持现在的快路径——整份内容引用加一，字节不动；第一次按块写入时才拆成段列表（惰性拆段，改动面最小）。
- **改其中一段**：段被共享则新写一段、列表改指向、旧段减一；段独占可原地改。
- **删文件**：列表逐段减引用，减到零才删字节。配额按段加减，禁止分叉时按整文件再记一份。
- 小文件未切块的，维持现在整份分叉即可，不必强行段化。

---

## 5. 明确不做的事（沿袭旧版，仍然全部有效）

- **不为「中间插入、后面错位」做 piece table**。那是另一层映射，代价是碎片与整理，本期不做。
- **下载不当作插入需求**。顺序下、续传是追加；Range 是按偏移覆盖。下载头用固定上限，不靠移位。
- **不做跨无关文件的内容去重**。只服务「同一份内容的副本」。
- **不接本机 APFS / 挂载卷 clone**。
- **不指望编辑器整文件另存仍共享**——从头到尾重写每段皆新，是写入方式问题。

## 6. 实施顺序（重排）

每步可单独验收。前两步与块化解耦、独立产生价值，先做。

### 6.0 第 0 步：堵两个现存缺口

- **安静写入门禁**：打开通道前查 `refCount`；大于 1 时回退到 VFS 范围写路径（那条路会正确分叉）。不做预分叉。
- **配额账目修正**：共享 OPFS 内容分叉时 `capacityDelta` 记实际新增字节，不再漏记整份拷贝。

### 6.1 段独立身份 + 引用

- 新建段索引：段 id → 引用计数、字节数、所在后端。IDB 段表与 OPFS 段文件都挂在这套身份下。
- 内容记录改为有序段引用列表；旧格式（整份 bytes / `[blobId, chunkIndex]` 块表 / 单文件 OPFS）**惰性兼容**：照常读写，第一次需要按块分叉时才拆段。
- 删除、孤儿清理、配额全部改成认段引用，避免「内容删了段还在」「段被两份共用却当独有删掉」。
- **落盘顺序固定为先写段字节、后提交引用记录**：以 IDB 为准的对账只能回收孤儿段，救不了「记录说有、字节没有」的真丢数据。

### 6.2 OPFS 正文段化

- OPFS 段以独立文件存放（按段 id 命名），内容记录不再对应单个 OPFS 文件。
- 读缺席段直接填零；顺序大写的追加路径保持流式行为。
- 已存在的单文件 OPFS 正文惰性迁移：首次按块分叉时拆段，平时不动。

### 6.3 复制快路径保持，写入改为按段分叉

- 复制：几乎零成本（元数据 + 引用加一）——现状已满足，回归即可。
- 范围写、覆盖写、流式覆盖、VM 镜像簇写：共享内容只为碰到的段分配新身份，其余段引用原样保留；独占内容原地改。
- 安静写入通道在段化落地后可解除回退，直接享受按段分叉。
- 引用判定与分叉放进同一写事务（现状读 / 写分离存在 TOCTOU 并发窗口，双写会双双分叉）；段化后写路径变多，此窗口必须收口。

### 6.4 配额与进度

- 共享后再写：配额增量 = 新段字节。
- 删一个副本：只释放因此归零的段，另一副本完整可读。
- 空间嗅探 / 设置用量 / 文件属性面板的分块数展示与账本一致。

### 6.5 回归面（必测）

- 复制后读两边相同；改一边另一边不变；删源留副本、删副本留源、两边都删后段消失。
- **OPFS 克隆后小范围写**：用量只涨所写段，且断言没有触发整份物理拷贝。
- **稀疏文件克隆后写洞边**、写零打洞不影响另一副本。
- **安静写入通道遇共享内容回退**且源文件不受污染；解除回退后同场景走段分叉。
- 流式覆盖共享文件、范围写共享、整块覆写共享、终端改前副本写入后源文件完好。
- 未分块小文件行为不变；v2 起各版本迁移用例继续通过（新增段索引迁移用例）。
- 配额口径：遍历节点实占之和与 `byte-total` 对账一致。

---

## 7. 成功长什么样

- 内部卷复制 GB 级镜像：瞬时完成，配额几乎不涨（现状已有）。
- 复制后 VM 往镜像里写几 MB：配额只涨所写段，无整份拷贝。
- 复制后改中间一小段的文本大文件：同上，两副本互不干扰。
- Finder / 本机磁盘用量不在验收范围；挂载卷复制仍是整份搬运，文档继续写明。

## 8. 决策点（动手前可默认如下）

- **默认做 6.0–6.4**；不做插入映射、不做全局去重、不做挂载 clone。
- **段粒度**：沿用现有槽大小（4MB 默认），与稀疏槽对齐，不引入第二套粒度。
- **OPFS 段化形态**：全局段对象 + 内容记录存有序引用（唯一能表达共享的形态）；否决「目录内私有副本」。
- **迁移策略**：惰性拆段，只在首次按块分叉时发生；不做一次性全量迁移。
- **安静写入通道**：先回退保正确，段化完成后再切回直写。
- 整份引用计数保留为快路径，第一次按块写再拆（沿袭旧版结论）。

## 9. 代价与对策（切碎不是免费的）

| 代价 | 具体表现 | 对策 |
|---|---|---|
| 写放大（固有） | 共享态下改 4KB 也物化整段 4MB（读旧段、打补丁、写新段） | 独占内容原地写快路径；粒度不再调细。APFS 同样存在，只是粒度更细 |
| 读路径变重 | 全量读从「1 个句柄一次流」变成数百段拼装；导出 / 下载不能整体递出一个 `File` | 段句柄上 LRU 缓存；下载器逐段 append 流 |
| Blob 组装内存峰值 | 预览 / 下载一次性 `new Blob([所有段])` 会整体拷贝 | 沿用 `filesReadBlobRange` 分段路径，改造面集中在导出器 |
| 元数据膨胀 | 内容记录从几十字节涨到每槽一条引用；`uniformChunkSize` 等长省空间技巧失效 | GB 级 ≈ 数百条引用、几十 KB，绝对量可忽略；禁止把列表塞进节点记录本身 |
| 崩溃一致性面扩大 | 元数据在 IDB、字节在 OPFS，两阶段窗口 × 段数放大孤儿概率；反向缺口是真丢数据 | 后台对账扫描 + §6.1 的固定落盘顺序双保险 |
| 格式蔓延 | 四种正文形态长期并存，每个新功能都要测全组合 | 见 §10 日落策略 |

不受影响：物理碎片化（浏览器本无布局保证）、随机簇读锁粒度反而变细、小文件不切段零变化、改名移动纯元数据依旧免费。

**为什么不用 APFS 的 4KB 粒度**：我们的「一块」是 IDB 记录或 OPFS 文件，单位成本比内核页高五个数量级。1GB 文件按 4KB 切 = 26 万个对象、仅引用元数据就约 20MB——记账开销与承诺节省的空间同量级，方案未生效先亏本。而收益早已饱和：4MB 粒度下改几 MB 只涨一段，「省 99.6%」到「省 99.96%」的边际改善不值千倍对象数。真有负载证据（如 VM 小簇高频分叉）再把 `DEFAULT_STREAM_CHUNK_SIZE` 下调到 512KB，一行配置的事。

## 10. 风险与前置验证（动手前必须先过）

### 10.1 需求频率未证实（最大的风险）

整个 §6.1–6.4 押在「用户复制 GB 级文件后再修改」高频发生上，目前没有埋点支撑。若真实触发率低，这就是过度工程。**§6.0 与本判断无关，无论如何都该做。**

- 前置动作：随 §6.0 埋两个计数器——「共享内容被范围写的次数」与「因此触发的整份拷贝字节数」，观察一段时间再决定是否启动后续步骤。

### 10.2 OPFS 句柄行为未实测

「数千段文件没问题」「LRU 能扛住 VM 散布写」目前是推断：同步访问句柄的独占语义、并发打开上限、FAT 表更新散布数百段时的缓存命中率，均未量化。最坏情形是句柄抖动使 VM 写入比单体文件更慢。

- 前置动作：先做一次 spike——用现有 FAT 卷测试夹具模拟段化 IO，量出吞吐与抖动曲线，达标才进 §6.2。

### 10.3 旧格式日落策略缺失

惰性兼容意味着四种形态（整份 bytes / IDB 块表 / OPFS 单体 / 段清单）无限期并存，回归矩阵持续膨胀。

- 默认方向：约定某个 DB 版本起后台闲时重写收敛到段清单；届时再定具体版本号。
