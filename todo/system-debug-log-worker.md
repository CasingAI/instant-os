# 系统诊断日志：独立 Worker 黑匣子

> 建立时间：2026-08-25
> 涉及项目：`instant-app`（系统诊断 / 主线程卡死 / IndexedDB）
> 状态：方案，未实施

目标：把系统诊断日志从主线程同步收集 + `localStorage` 快照，改成 **开关可控的埋点 + 独立 Worker 收集 / 心跳 / 落盘**。高危路径可以打得很勤；关掉开关时调用几乎是空操作；主线程死循环时仍能留下临终尾巴，并记一条「主线程未响应」。

本文只覆盖 **系统诊断日志**（现在「事件日志 → 系统」那一栏）。AI 事件日志、应用内 console、QuickJS 客户机 stdout 不在本期。

---

## 1. 为什么要改

### 1.1 现在的致命问题

当前收集器完全跑在页面主线程上：

- 调用点（QuickJS 求值、客户机 fs 采样、VFS 慢解析、`npm run`、开机启动项）在主线程里往内存环形缓冲追加。
- 按「每 64 条且至少隔约 1.5 秒」把整环同步 `JSON.stringify` 进 `localStorage`。
- 界面刷新靠主线程 `setTimeout` 发自定义事件。

浏览器里 JavaScript 是单线程的。主线程一旦卡死或进入死循环：

- 新日志排不上队（除非卡死那串代码自己还在调用追加）。
- 上一轮还没落到 `localStorage` 的尾巴困在内存里，标签被杀就丢。
- 当前标签往往点不了「复制最近诊断」；只能靠新开标签读上一份 live 快照，这是现在文案已经承认的退路。

高危路径（VFS 扫树、`tsc`、客户机文件系统、`npm run`）正是最容易把主线程打死的地方，也是最需要面包屑的地方。收集器和故障抢同一条事件循环，故障发生时收集器先死。

### 1.2 不能靠 Console

开发者工具会把打印出来的内容一直挂在控制台缓冲里，几乎不设上限。高危点一旦进入风暴，等于往一个只增不减的缓冲区塞字符串；工具开着时还有格式化、对象保留、源码映射。诊断本身就能把主线程打满，而且系统收集器也读不到它。

高危路径禁止走 `console`。

### 1.3 本期要得到什么

1. **主线程热路径只做一件极便宜的事**：看开关 →（若开）把很短的字段丢给 Worker。不写盘、不等待、不刷新界面。
2. **Worker 有自己的事件循环**：缓冲、合并、落盘、心跳都在这里。主线程冻住时 Worker 仍能跑。
3. **心跳超时 → 立刻记「主线程未响应」**，并紧急刷盘。不依赖已经冻住的页面回消息。
4. **死循环过程中，只要循环还经过已埋点的代码，日志仍能进 Worker**。`postMessage` 在调用当下就会把数据排进 Worker 队列，不需要主线程回到事件循环。
5. **开关关掉 = 真正空操作**。默认建议关掉（与现在默认开相反）。
6. **独立 IndexedDB 库**：不进数据空间账本，设置里单独看占用、单独清空。落盘形态只有字符串。

## 3. 工作原理（方案约束，必须遵守）

这些不是实现细节，是浏览器规则。违反等于方案作废。

### 3.1 两条事件循环

页面主线程和 Dedicated Worker 各有一条事件循环，调用栈不共用。

主线程上的事分成两类：

- **已经在栈上跑着的代码**：死循环、长时间同步计算、QuickJS 一段不让出的求值。
- **还在队列里等着的事**：定时器、点击、Worker 回消息、IndexedDB 在主线程上的回调。栈不空，这些永远轮不到。

### 3.2 `postMessage` 不是后台通道

主线程调用 `worker.postMessage(...)` 时，浏览器在**这一刻**做结构化克隆，并排进 **Worker 自己的队列**。之后不需要主线程再冲刷一次。

因此：

- 死循环**体内**如果执行到了发送，Worker **能马上收到**。
- 死循环**体外**那些等着发的东西（节流到期再写、`setTimeout` 再通知、等心跳再回复）**全部发不出去**。
- 空转的 `while (true) {}`、或 QuickJS 客户机纯计算死循环中间不进宿主埋点：Worker 收不到新面包屑，只能靠心跳判定未响应，原因只剩卡死前最后几条。

不是「死循环了主线程仍能自动发消息」，而是「**死循环里碰巧执行到的那几次发送，仍然有效**」。

### 3.3 心跳检测靠「回不了」

Worker → 主线程的 ping 能进主线程队列，但卡死时处理不了，自然也回不了 pong。超时即可记「主线程未响应」。这是判据，不是缺陷。

主线程恢复后可能突然收到一串过期 ping，必须丢弃或合并，不能在主线程上为每条 ping 做重活。

### 3.4 参数在进函数之前就算完

JavaScript 会先求值实参再调用函数。关闭开关只能省掉**函数里面**的活。调用处如果先 `截断(很长的路径)`、先 new 一个大对象，关掉也已经花过钱。

高危点：能传现成原始值就传原始值；贵的细节用延迟计算，或先看内存开关再决定要不要构造。

### 3.5 IndexedDB 分库 ≠ 磁盘分家

同源下多个 IndexedDB 库共用一块来源配额、同一条存储进程。单独建库隔离的是 **事务、版本、产品账本**，不是物理磁盘。诊断写满仍可能让文件库、数据空间一起报配额不足。

诊断库必须自带覆盖窗口或体积顶，只打诊断自己；清空只删诊断库。

IndexedDB 的磁盘工作多半在浏览器存储线程。从 **Worker 发起** 的读写，回调在 Worker 上，不需要主线程活着。从主线程发起则回调要等主线程空出来。结构化克隆发生在**调用线程**：所以 `put` 必须在 Worker 里做，且对象要短。

## 4. 目标架构

```
高危 / 生命周期埋点（主线程）
    │  开关关：立即 return（只读内存布尔）
    │  开关开：短字段 postMessage（或写入共享环）
    ▼
诊断 Worker（独立事件循环）
    ├── 时间线环（小，几乎不采样，不被热路径冲掉）
    ├── 热路径环（写满覆盖）
    ├── 计数器（次数、丢弃数、最慢一次、最近窗口）
    ├── 心跳：定期 ping 主线程；超时 → 记「主线程未响应」+ 紧急刷盘
    └── 落盘：独立 IndexedDB，覆盖写快照；字符串正文
            │
            ▼
新标签 / 设置 / 事件日志界面
    └── 问 Worker 或直接读诊断库（不经过数据空间账本）
```

### 4.1 线程职责

**主线程只允许：**

- 读内存开关。
- 开关打开时发送一条已经很小的记录（层、操作名、可选已是字符串的细节、可选耗时、时间戳）。
- 响应心跳 pong（空操作级，只回一个序号或时间）。
- 把 Worker 推来的「环有更新」做节流后的界面刷新（卡死时本来也刷不了，这是预期）。

**主线程禁止：**

- 热路径写 `localStorage` / IndexedDB / OPFS。
- 热路径 `JSON.stringify` 整环。
- 热路径打开诊断库、升级版本。
- 为日志等待 Worker 回复。
- 通道堵了就同步重试或阻塞业务。

**Worker 负责：**

- 对象 → 字符串（安全截断）。
- 合并相同操作短窗口内的重复。
- 两个环 + 计数器。
- 平时节流覆盖写库；心跳超时立即刷。
- 处理不过来时丢最旧或丢本条，并给计数器加「过载丢弃」。
- 响应界面：列出当前环、残留、复制文本、清空。

第一版用 **Dedicated Worker** 即可：实现简单，和页面同生共死。新开标签靠 Worker 已经写入的 IndexedDB 看到残留（延续现在「卡了请新开标签」的产品路径，只是残留从 `localStorage` 换成诊断库）。

跨标签 Shared Worker 能让新标签直接连上还在跑的收集器、连没落盘的尾巴都能问到，作为后续优化，不挡第一版。页面被浏览器强制杀死时 Dedicated Worker 也会没，所以 Worker 里也必须勤落盘，不能只堆内存。

### 4.2 两层环，禁止混冲

风暴时 1024 槽的单环会被几毫秒的 `resolveNode` 冲光，界面上只剩长得很像的路径，看不出是谁在跑。

| 环 | 容量量级 | 谁可以进 | 覆盖策略 |
|---|---|---|---|
| 时间线 | 很小（几十到一两百条） | 任务开始/结束/失败、求值入口、实例销毁、开关变更、**主线程未响应** | 几乎不采样；热路径禁止写入 |
| 热路径 | 较大（约 1k～4k 条，第一版可先 1024） | fs / VFS / require 等 | 写满覆盖最旧 |

另加 **计数器**（几乎免费）：每层次数、最近窗口耗时、最慢一次、通道丢弃数。环被覆盖后仍能知道「解析了两百万次，环里只剩最后一千次」。

心跳判定未响应时，三条一起落盘：时间线 + 热路径尾巴 + 计数器。

### 4.3 插桩密度 vs 落环密度

高危点可以**每次都碰到记录器**（以便死循环只要还经过这些点，黑匣子里就还有字），但不一定每次都变成一条可展示记录。

建议档位（开关打开时）：

1. 先加计数。
2. 超过耗时阈值才生成一条完整记录（现状 VFS >8ms、fs >16ms 可保留为默认热路径策略，密度可调）。
3. 相同层 + 操作 + 细节在短窗口合并成「重复了 N 次」。
4. 每层每秒进环条数封顶，多出来只加计数。

「打开开关」不等于「每次调用都落一条、都写盘」。打开只表示允许进黑匣子；黑匣子仍然覆盖写。

### 4.4 通道

主线程 → Worker：只发短字段。不要把整棵节点、Blob、文件全文塞进去。结构化克隆发生在主线程，风暴时克隆本身会加重卡顿。

若第一版 `postMessage` 在最热路径上仍可测到明显成本，再考虑共享内存环（主线程只写预先分配的槽）。那是优化，不是第一版必做。

Worker 处理不过来：明确丢弃，记下丢了多少。「日志系统过载」本身是诊断信号。永远不要反过来阻塞 VFS / QuickJS。

## 5. 埋点 API

对外一个很窄的入口，替换 `appendSystemDebugLog`。旧名字可以短期内做成包装，最终只留一个。

### 5.1 调用方可以传什么

- **层**：沿用现有分层（`npm` / `qjs` / `qjs-fs` / `vfs-resolve` / `require` / `system`），需要的话可加 `heartbeat` 或把「主线程未响应」归入 `system`。
- **操作名**：短字符串，如 `eval-start`、`resolveNode`。
- **细节**：字符串 **或** 浅对象。调用方不必自己拼句子。
- **耗时**：可选数字。
- **时间戳**：默认 Worker 或主线程发送时打；卡死路径以发送瞬间为准。

对象随它传，内部处理。不要在类型上禁止对象，也不要鼓励传任意巨大结构。

### 5.2 内部怎么变成字符串

落盘和展示最终 **只存字符串**。

对象处理规则（必须有死规矩，避免一次序列化把线程打挂）：

- 只遍历有限深度、有限键数、有限总长度。
- 循环引用、无法克隆的值：改成占位，不要抛到业务里。
- 路径类字段继续只留末几段（现有 `shortenDebugPath` 的语义搬进内部处理，调用方可不截）。
- 序列化 **仅在开关已打开之后** 做，并且 **放在 Worker 里** 做。主线程热路径不要 `JSON.stringify` 用户对象。

字符串细节：截断到合理上限（建议单条几百到一两千字符量级），超了加省略标记。

### 5.3 高危点怎么埋

现有埋点都保留，改为走新入口；高危点加强的是「碰得到记录器」，不是「每条都全量落盘」：

| 位置 | 现在 | 本期 |
|---|---|---|
| `package-run` 的 run/segment/script 起止 | 已有，且 `force` | 进时间线环 |
| QuickJS `eval-start` / `eval-error` / `destroy` | 已有 | 进时间线环 |
| 客户机 fs（`beginFsHostTrace`） | 采样 | 开关开时每次计数；完整记录仍采样 + 阈值 |
| VFS `resolveNode` | 仅 >8ms | 开关开时每次计数；完整记录仍阈值；可提高采样或把阈值做成可配，但默认不能全量进环 |
| 开机启动项 | 已有 | 进时间线环 |
| 新 | 无 | Worker 心跳超时写入时间线：「主线程未响应」，带最后一次成功 pong 的时刻、已丢失次数 |

禁止在这些点 `console.log`。

生命周期事件不再用 `force` 打穿用户开关。用户关掉就是全部不记（含时间线）。若未来要「关诊断仍记崩溃」，另开极低频通道，不和本入口混用。

## 6. 开关

### 6.1 产品

- 位置仍在开发者设置「系统诊断日志」。
- **默认关闭**（现状默认开，要改；否则所有用户都在给高危路径交税）。
- 关闭时：埋点函数读内存布尔后立刻返回；Worker 可停心跳、停写库（已落盘的残留仍在，直到用户清）。
- 打开时：才启动或恢复 Worker、心跳、进环、落盘。
- 文案要写清：打开会在高危路径上产生开销；整页卡死后请新开标签看残留；本数据不计入数据空间。

### 6.2 实现

- 内存里一颗布尔，启动读一次，设置变更时更新。
- **禁止** 每次埋点都 `localStorage.getItem` + `JSON.parse`（这是现状最大的性能坑之一）。
- 设置存储可以继续放在现有系统配置 / `localStorage` 键里（开关本身极低频），与诊断正文库分开。

界面关掉后不必删除每个调用点；空操作即可。

## 7. 存储

### 7.1 独立 IndexedDB 库

新建一个 **只给诊断用的库**，不要在 `instant-os-data` 里加 store，也不要写进 `instant-os-files`。

理由：

- 诊断升版本不会去碰数据空间已经不小的版本号。
- 诊断事务失败不会把事件日志、文件节点一起中止。
- 清空诊断不动用户数据。
- **不进入数据空间那套容量记账**（8GB 那条）。产品上这就是「和数据空间内容不共享的一块」。

设置 → 存储空间：不要把诊断字节加进数据空间圆环。可在开发者设置或存储页另给一行「系统诊断日志」占用 + 清空，避免用户找不到体积从哪来。

### 7.2 「不设上限」的准确含义

产品账本：不跟数据空间抢那 8GB，不按那套规则驱逐用户文件。

实现：诊断库 **必须自带死上限**（覆盖写最近若干份快照，或总大小到顶丢最旧）。浏览器同源配额仍与文件库、数据空间共用。无窗口的「来一条 append 一条」会在开关打开 + 高危风暴时打满整站配额，文件写入失败，卡死标签又打不开设置。

建议第一版：

- 库里只保留：当前 live 快照 + 若干份历史 / 未响应当场快照（份数固定，覆盖最旧）。
- 每份快照 = 时间线环 + 热路径环 + 计数器，正文都是已经处理好的字符串行。
- 平时按时间节流覆盖 live（量级可沿用「约 1.5 秒」或「环有实质变化」）；心跳超时额外写一份「未响应快照」，不要等节流。

不要用主线程 `localStorage` 继续当主方案。迁移期可读旧 live/residual 键一次，导入后删除，避免两套残留。

### 7.3 谁读写这个库

- **只有诊断 Worker** 打开并长期持有连接、负责升级。
- 主线程热路径禁止 `open`。
- 事件日志界面：向 Worker 要当前内存环；新标签 Worker 启动时从库读出 residual。
- 若界面偶尔直接读库，只能是冷路径（打开面板、设置清空），且不能和 VFS 热路径缠在一起。

写失败：丢弃本轮落盘，计数 +1，不要在主线程重试，不要弹窗打断故障现场。

Worker 里没有 `localStorage`。不要为了「和现在一样」在 Worker 里设法绕回 `localStorage`。

## 8. 心跳与「主线程未响应」

与现有 **沙箱应用窗口心跳**（iframe 丢拍 → 卡死对话框）分开。那条只说明某个生成应用窗口；本条说明 **整页宿主主线程**。

流程：

1. 开关打开且 Worker 活着时，Worker 按固定间隔 ping 主线程（间隔需明显长于正常一帧，又要短到卡死后几秒内能宣判；建议秒级，具体实施时再定）。
2. 主线程 pong 必须极便宜（不读盘、不分配大对象）。
3. 连续若干次无 pong → 记时间线「主线程未响应」，带已持续时间、最后成功 pong 时刻；立即把两环 + 计数器写入诊断库。
4. 之后可以降频继续 ping，避免恢复后被过期 ping 打爆；恢复后记一条「主线程恢复」（可选，第一版可以没有）。

卡死当下当前标签 UI 仍可能动不了。新开标签读库应能看到未响应快照。这是对现有「请新开标签查看上次会话残留」的升级，而不是要求冻住的页面还能点按钮。

卡死对话框上的「复制最近诊断」：能点时仍从主线程内存镜像或问 Worker；不能点时只能靠新标签。不要承诺冻住的页面一定能复制。

## 9. 界面与设置

### 9.1 事件日志 → 系统

- 仍展示当前会话时间线 + 热路径（可按层过滤，第一版可先平铺，时间线置顶或分段）。
- 保留「上次会话残留 / 未响应快照」。
- 复制、清空当前、隐藏残留。清空当前 = 清内存环 + 清 live；是否同时清库里的历史快照要在设置里另给「清空诊断数据」，避免误删现场。
- 提示：采样/黑匣子、Worker 落盘、卡死后新开标签、不计入数据空间。

### 9.2 开发者设置

- 总开关（默认关）。
- 占用体积（Worker 或冷路径读库估算）。
- 清空诊断数据。
- 不要在第一版做一堆采样旋钮；密度用代码默认值。若阈值要可配，第二版再说。

### 9.3 存储设置

诊断占用 **不计入** 数据空间圆环和「事件日志」那一项（那一项是 AI 事件日志）。可单独一行或只放在开发者设置，避免和 AI 事件日志混淆。

## 10. 明确不做

- 不把诊断正文写入数据空间 IndexedDB。
- 不用 Console 当收集器或备份通道。
- 不在主线程热路径做 IO 或整环序列化。
- 不保证空转死循环（不经过埋点）能留下循环体内的逐步记录。
- 不保证页面被浏览器强制杀死后，Worker 内存里未落盘的最后几毫秒还在。
- 第一版不做 Shared Worker、不做 SharedArrayBuffer 热通道（列为后续）。
- 不把 AI 事件日志迁到这个 Worker。
- 不把沙箱 iframe 心跳和整页心跳合成一个指示灯（可以在文案上区分）。

## 11. 实施顺序

做完一步再开下一步。每一步都应能单独合入，不出现「半套主线程 IO + 半套 Worker」长期并存。

### 11.1 开关改成内存布尔，默认关闭

改 `system-debug-log-settings-storage`：启动缓存、变更更新；`isSystemDebugLogEnabled` 只读内存。默认 `enabled: false`。开发者设置文案同步。现有埋点先不加密，只把「每次读盘」这个坑填掉。

### 11.2 抽出「字符串化 + 两环 + 计数器」的纯逻辑

可单测：对象截断、路径缩短、重复合并、环覆盖、时间线不被热路径冲掉。这一层不要碰 DOM、不要碰 IndexedDB，便于 Worker 和测试共用。

### 11.3 Dedicated Worker + 主线程门面

主线程：开关关 return；开则 `postMessage`。Worker：进环、节流通知主线程刷新。此步仍可不写 IDB，先验证风暴时主线程开销和卡死时 Worker 仍能收热路径消息（用故意死循环 + 循环内埋点的测试页或单测思路）。

### 11.4 心跳

Worker ping / 主线程 pong / 超时写时间线。用故意占满主线程的测试确认：能宣判未响应，且循环内埋点仍在热路径环里。

### 11.5 独立 IndexedDB

Worker 打开诊断库，覆盖写 live，未响应时加快照。新标签启动读 residual。删掉 `localStorage` live/residual 主路径；做一次迁移读取后删除旧键。

### 11.6 界面与设置

事件日志面板改读 Worker/库；开发者设置增加占用与清空；存储圆环确认不含诊断字节。卡死对话框文案改为「新开标签读诊断库残留」。

### 11.7 埋点收口

所有 `appendSystemDebugLog` 改为新入口；去掉 `force` 打穿开关；高危点确认计数在每次调用都会加（开关开时），完整记录仍采样。禁止新增 `console.log` 诊断。

### 11.8 清理

删除主线程 `persistSnapshot`、`SNAPSHOP_*`、`LIVE_STORAGE_KEY` 等。确认 `storage` 事件跨标签逻辑被「各标签自己的 Worker 读同一诊断库」或启动抬升取代。

## 12. 测试计划

### 12.1 开关

- 关闭时：热路径调用不 `postMessage`、不分配条目、不读 `localStorage`。
- 打开/关闭切换立即生效（内存布尔），不必重载页面。
- `force` 不再绕过关闭状态。

### 12.2 序列化

- 字符串原样（超长截断）。
- 浅对象变成稳定短字符串。
- 循环引用、超深、超多键不抛、不爆内存。

### 12.3 环

- 热路径写满只覆盖热路径，时间线上的 `eval-start` 还在。
- 计数器在采样丢弃时仍增加。
- 合并「短窗口相同记录 × N」。

### 12.4 Worker 与卡死（核心）

- 主线程故意同步死循环，循环体内埋点：Worker 能收到新记录，且心跳宣判未响应，库里有未响应快照。
- 主线程故意同步死循环，循环体 **不** 埋点：Worker 仍宣判未响应，热路径不再增长，时间线有未响应，残留是卡死前最后几条。
- 卡死过程中主线程 `setTimeout` / 界面刷新可以不发生（预期）。
- 新开上下文（测试里即新开库连接）能读到未响应快照。

### 12.5 存储隔离

- 诊断写入不增加数据空间 `byte-total`。
- 清空诊断不删 `instant-os-data` / `instant-os-files`。
- 诊断库写满自己的窗口时覆盖最旧，不无限 append。

### 12.6 回归

- 开发者设置开关、事件日志系统栏、卡死对话框复制（未卡死时）。
- `npm run` / QuickJS eval 起止仍能出现在时间线（开关开时）。
- VFS / fs 风暴下打开开关，主线程不应被诊断 IO 打满（对比改前 `localStorage` 整环 stringify）。

浏览器里无法用单测完全模拟「用户点强制杀死标签」；文档化即可。

## 13. 风险与取舍

| 风险 | 处理 |
|---|---|
| 打开开关后 `postMessage` 克隆仍太贵 | 热路径只传标量；再不行上共享内存环（后续） |
| 诊断写 IDB 与文件风暴抢同源存储进程 | 覆盖写小快照、低频；失败即丢。若仍可测到抢盘，后续改 Worker 内 OPFS 覆盖一个小文件 |
| 默认改关，现有依赖「默认就有面包屑」的排查习惯 | 用文案说明；卡死对话框提醒去打开开关（对「已经卡死的这一次」来不及，只对下一次） |
| Dedicated Worker 随页死 | 靠落盘 + 新标签；Shared Worker 后续 |
| 用户把任意大对象传入口 | Worker 截断；主线程不 stringify |
| 与 iframe 卡死对话框同时出现 | 文案区分「应用未响应」和「整页未响应」 |

## 14. 验收标准

1. 开关关闭时，高危路径上的记录调用在性能上接近空函数（只读内存布尔），且无 IO。
2. 开关打开时，主线程热路径无诊断 IO；落盘只发生在 Worker。
3. 主线程死循环 + 循环内埋点：Worker 同时具备「未响应」记录和循环内日志尾巴。
4. 新标签能从独立诊断库读到残留 / 未响应快照，不依赖冻住标签的内存。
5. 诊断数据不计入数据空间容量；可在设置中单独清空。
6. 落盘内容为字符串行；调用方可传对象。
7. 不再使用 `localStorage` 作为诊断正文主存储。
8. 高危点没有新增 `console.log` 风暴路径。
