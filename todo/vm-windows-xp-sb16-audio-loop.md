# Windows XP 声音尾段反复播放

> 建立时间：2026-08-23  
> 涉及项目：`Instant-virtual-machine`（v86 SB16 + 浏览器扬声器链路）  
> 优先级：低（不影响开机与基本使用；XP 短音效可接受时再优化）

## 现象

在 `Instant-virtual-machine` 里运行 Windows XP，声音能正常从头播到尾，但结尾一小段会反复播放，常达十几次甚至更久。整体听感卡顿，不像单纯的爆音或变速。

客机内已按 v86 文档配置：Standard PC、手动安装 Sound Blaster 16 WDM 驱动、扬声器在虚拟机设置中开启。调整硬件加速、采样率等 XP 声音选项无效。

## 根因（推断）

客机侧声音能完整播出，说明声卡、中断、驱动基本可用。问题出在**一段缓冲播完之后的衔接**：

1. XP 的 SB16 WDM 驱动使用 DMA 自动循环模式：一块内存播完后应触发中断，由客机填下一块或发停止。
2. v86 的 SB16 在整块计数归零时会立刻把「剩余字节」重置并继续抽同一块内存，同时向 CPU 发中断。
3. 浏览器侧的播放队列按自己的时钟持续向模拟器要数据，不会等客机处理完中断。
4. 若客机（XP + WDM）在中断处理上偏慢，或播放队列一次要的数据偏多，最后那一小块会在客机尚未更新缓冲前被**重复抽取多次**送扬声器。

这与 QEMU 上 SB16「冻住并循环最后一小段」类问题同源，属于模拟器与客机驱动时序不匹配，**不是** XP 里再调一个隐藏开关能解决的。

Instant-virtual-machine 当前仅透传 v86 的 `disable_speaker` 开关，无第二套声卡（如 AC97）可换。

## 已排除的无效方向

- 客机：DirectSound 硬件加速拉到无、降低采样率、确认 IRQ/DMA 资源
- 宿主：仅开关扬声器、调内存/ACPI（Standard PC 仍需要，但不治尾段循环）

## 待办（未来视情况优化）

### 1. 在 v86 SB16 层收紧「播完一块」后的行为

位置：`Instant-virtual-machine` 内嵌的 v86（`public/vendor/v86` 或 vendor 源码）。

思路：DMA 块计数归零并发出中断后，在客机应答中断或显式停止之前，**不要**立即按 autoinit 继续抽下一块；或限制连续抽取次数，避免同一尾段被排队十几遍。

需对照真实 SB16 与 Windows WDM 驱动的双缓冲语义，避免修尾段循环却弄坏连续播放。

### 2. 在浏览器扬声器层避免空转要数据

位置：v86 `speaker` 模块（AudioWorklet / BufferSource 两条 DAC 路径）。

思路：播放队列见底时，若 SB16 侧已无新样本且处于「等中断」状态，暂停 pump，而不是用空缓冲或重复块填满队列。

### 3. 验收标准

- XP 系统提示音、短 wav：播完后 **1 秒内** 安静，无尾段循环。
- 连续音乐/较长 wav：可接受轻微断续，但不应在句末卡死十几遍。
- Win98 / Win2000 回归：不因改动导致原本可用的场景变坏。

### 4. 可选：文档与用户预期

- 在虚拟机帮助或 XP 相关说明中注明：当前 SB16 在 XP 上尾段可能循环，属已知限制。
- v86 上游若已有相关 issue/PR，升级 vendor 时一并跟进。

## 决策点

- 是否值得 fork/patch v86，还是等上游修复后再升级 vendor？
- 优化优先级是否低于 `todo/vm-xp-3d/` 三维通路（建议：是，除非用户强依赖 XP 内音效）？
- 若短期不修：是否仅在 XP 预设/文档里标注「声音已知问题」，避免用户反复试客机设置？
